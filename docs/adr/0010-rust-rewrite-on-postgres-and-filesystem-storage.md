# Rust rewrite on Postgres and filesystem storage

The server is rewritten in Rust (tokio, axum, SeaORM 2) and supports exactly one database, Postgres, and one storage backend, the filesystem. SQLite, MySQL, S3 and GCS are dropped. Postgres is what multi-replica deployments already need, and one database lets the schema use Postgres features directly: `timestamptz` columns, a `"C"`-collated `key` so a single `(repo_id, scope, version, key)` index serves both exact and `LIKE 'prefix%'` restore-key lookups, unique keys that make Upload creation and Cache Entry replacement single upserts (`ON CONFLICT`) instead of read-then-write races, a single-statement Merge Lease takeover, and transactional, advisory-locked migrations so replicas can start together. Dropping object storage removes Server-side Merge and direct downloads (ADR-0009's S3/GCS paths); `ENABLE_DIRECT_DOWNLOADS` is accepted and ignored.

Because the schema changed (snake_case columns, UUID keys, `size_bytes NOT NULL`), the first migration drops the TypeScript server's tables when it finds Kysely's migration table. This follows the precedent of the earlier scope and repository-id migrations: cache data is disposable. The dropped folders become Orphaned Storage and are reclaimed after the grace period (ADR-0001); Storage Reconciliation of sizes is no longer needed because every Storage Location records its size at creation.

Filesystem I/O goes through `tokio-uring`. Its runtime is current-thread, so a small pool of worker threads each own a ring and run file jobs (open, read, write, statx, rename, unlink, mkdir) handed over from the multi-threaded server runtime by channel. Operations io_uring has no opcode for — readdir, statvfs, recursive deletion — run on tokio's blocking pool. A ring is probed at startup; where the kernel or a seccomp profile (Docker's default among them) refuses io_uring, the server logs it and falls back to `tokio::fs`.

Behavior is otherwise preserved, including the lease model (ADR-0002), atomic visibility (ADR-0004) and dangling-entry self-heal (ADR-0005), with two hardenings: a merger rejects a merged object whose length differs from the recorded payload size before it becomes visible, so a truncated feed can never be marked merged; and a client that disconnects during the first, merging download no longer aborts the Merge. Metrics remain per process (ADR-0007), now with a single process per container.
